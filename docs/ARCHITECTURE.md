# 架构

## 数据流

```
课程讲义 (courses/<id>/*.md)
      │  ① 构建期：白名单校验 + 切块 + 记哈希
      ▼
知识包 (packs/<id>/<chapter>.json)
      │  ② 构建期：每块算向量（本地模型）
      ▼
向量索引 (packs/<id>/vectors.json)
      │
学生提问 ──③ 意图判断──→ 讲法（5 选 1）
      │  ④ 混合检索：词法排名 + 向量排名 → RRF 融合 → 预算装配
      ▼
提示词（讲法细则 + 讲义摘录 + 目录）
      │  ⑤ 模型生成
      ▼
引用校验（逐个比对块编号）──⑥ 落库 + 额度扣减
      │
      ▼
学生看到带角标的回答；教师后台看到全部提问与卡点
```

三个关键点是**代码层**而不是提示词层：

1. 教师版/答案在 ① 就被拒绝，不进知识包
2. 引用在 ⑤ 之后逐条校验，编造的编号直接作废
3. 额度在 ④ 之前检查，用完不产生模型调用

## 为什么切块按 `##` 和 `**例 X.Y-N**`

数学讲义的结构天然是「小节 + 例题」。按这两级切，每块既够小（检索准），又自成完整语义单元（模型能直接讲）。标题会一起进上下文和向量，因为它本身带强语义（`§1.4 线性相关与线性无关` 比正文更能说明这块讲什么）。

实测过的三个反直觉结论：

| 做法 | 结果 |
| --- | --- |
| 整块正文嵌入 | 问「反函数组定理」时正确块只有 0.53，例题块 0.59 反而更高 |
| 标题 + 正文前 600 字 | 0.55；只嵌标题能到 0.67，但内容查询会变差 |
| 清洗 LaTeX 后再嵌入 | 同一块 0.53 → 0.64，因为 `$`、`\partial` 是噪声 |

## 为什么向量排序要排除「枢纽块」

单元标题、章标题这类块的语义最泛，向量空间里离所有查询都近，会把真正的答案挤下去。实测不排除时 Top1 从 35% 掉到 15%。排除后它们仍能被词法命中，只是不参与向量排名。

## 为什么用 RRF 而不是加权分数

词法分是「命中二元组数 / 长度归一」，量纲随意；余弦相似度在 0~1 之间。两者直接加权需要调归一化，换个语料就失效。RRF 只看名次，天然免疫量纲问题，代价是丢掉「差多少」的信息——对「选出该讲哪块」这个任务足够。

## 状态与存储

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 问答流水 | SQLite `data/assistant.db` | 提问、回答、引用、状态、token、反馈 |
| 学生额度覆盖值 | 同上，students 表 | NULL = 跟课程默认，0 = 不限 |
| 额度用量 | 不单独存 | 每次从流水现算，永远和事实一致 |
| 访问码 | `config/students.json`（哈希）+ `data/codes.md`（明文流水） | 两处必须同步，由 `src/students.js` 统一维护 |
| 学生画像 | `students/<目录>/学生画像.md` | 文件是唯一真相，服务只读写 |
| 知识包 / 向量 | `packs/` | 可删可重建 |

## 降级策略

任何一环坏掉都不应该让答疑停摆：

| 坏掉的部分 | 结果 |
| --- | --- |
| 向量索引缺失或过期（`packVersion` 不匹配） | 自动退回纯词法 |
| 模型下载失败 / 未安装依赖 | 自动退回纯词法 |
| 检索无结果 | 直接回「无依据」，不调模型 |
| 模型返回无有效引用 | 标记「未定位」，照常展示并进后台待办 |
| 模型接口失败 | 返回错误信息，不扣额度（额度按流水算） |

## 扩展点

- **换模型**：`.env` 里换 `LLM_PROVIDER`，或填 `OPENAI_BASE_URL` 接任意兼容端点
- **换向量模型**：`EMBED_MODEL` + `scripts/fetch-model.sh`，重建索引即可
- **调检索权重**：`FUSION_VEC_WEIGHT`，改完跑 `npm run eval`
- **加讲法**：`src/intent.js` 加一个 kind，`src/answer.js` 的 `KIND_SPEC` 加一套细则
- **加额度维度**：`src/quota.js` 的 `DIMENSIONS` 与 `evaluateQuota` 的顺序表
